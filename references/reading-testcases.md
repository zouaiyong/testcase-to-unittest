# 读用例：testcase-design 的两种产物

用例来自 `testcase-design` 时按下表读；别的来源只要有稳定编号和逐行预期，按同样的口径对应。

| 用例里 | XMind 版 `{需求名称}-测试用例.md` | Excel/CSV 版 `{需求名称}-测试用例.csv` | 测试里对应 |
|---|---|---|---|
| 编号 | 用例标题开头的 `TC-####` | 「用例编号」列 | `文件名#TC-####` 回指 |
| 前置 | 标题里的条件；用例在 `#####` 时，再加上它所属 `####` 场景分组名里写的共用状态 | 「前置条件」列 | 准备数据、打桩 |
| 操作 | 标题里的操作 | 「测试步骤」列 | 调用被测方法 |
| 判据明细行 | `预期结果` 下的每个 `-` 行 | 「预期结果」列的每个编号行 | 一行一个断言，或登记为不可单测 |

## 哪些算判据

- 判据只认已经放进项目 `doc/testcases/` 的用例文件。`## 范围声明` 里列为「不测」的不进任何清单；「需求缺口」影响到的用例行已各自标了【待确认】，按行处理即可；
  源目录里的 `work/`（需求原文、拆解、评审报告）和 `_archive` 不复制，也不当判据
- 同目录的 `{需求名称}-评审指引.md`：CSV 版没有范围声明，范围与待确认写在这里；状态还是「待拍板」的项，涉及的判据行在拍板前按【待确认】处理
- 同一需求同时有 md 和 csv 时，先问用户以哪份为准，另一份不进 `--docs`
- 用例文档**只引用不复制**。测试代码用 `文件名#TC-编号` 回指，用例文档始终是唯一事实源。
  若流程上必须复制副本（如复制到 `doc/testcases/`），要声明「副本只读、判据以原件为准」

## 判据行怎么归层

- 预期写的是页面表现（跳转、展示、提示出现在哪）的行，归人工层；后端能断言的是返回值、异常与提示文案、对协作方的调用与入参
- 预期里顺带点名的其余无效类（如「手机号为空同样拦截」）是额外的输入，各要一组测试数据，估预期方法数时算进去
- CSV「验证维度」列只作分层初判，最终看每一行判据的内容：

| 验证维度 | 初判 |
|---|---|
| 功能 / 边界 / 异常 | 规则层；写成计算公式的行 → 纯口径层 |
| 权限 / 安全 | 校验写在业务代码里的归规则层，靠框架过滤器或网关的归集成层 |
| 数据一致性 / 并发 / 集成 | 多为集成层 |
| 兼容性 / 用户体验 | 人工层 |
| 性能 | 不在本 skill 范围 |
