# 断言规则

写测试（阶段 3）时逐条对照；评审（阶段 4）按 review-dimensions.md 的维度反查这些规则有没有被绕过。
每条规则后面是它防的那种假绿——规则本身可以忘，知道它防什么就能自己推回来。

| # | 规则 | 防的是什么 |
|---|---|---|
| 1 | 数值断言同时锁**值和小数位**，用字符串形式（如 `toPlainString()`）比对 | 很多语言的十进制相等比较忽略标度，`1.0` 与 `1.0000` 被判相等，精度判据形同虚设 |
| 2 | 文案判据**逐字**比对，不用包含匹配 | 包含匹配下改错半句话仍绿 |
| 3 | 判据写「按 X+Y+Z 维度」的，必须真的断言到维度入参；断言不到就在用例名里**明说验不了** | 用例名声称验证了维度、实际 mock 把条件吞了，是空头承诺 |
| 4 | 「合计恒等于总额」这类不变量，**每组夹具都要验** | 只验一组，其余组的尾差分配错了没人知道 |
| 5 | 不用弱断言：「大于 0」该写成「等于 1」；判据写了文案却只断异常类型不断消息，等于没断 | 断言太松，改坏了也不红 |
| 6 | 判据没给文案（如只写「提交被拦截」）时，断言「被拦截 + 副作用没发生」，并证明拦下它的是**这条**规则：其余校验用夹具放行，断言这条规则确实执行到了。代码里现有文案要锁只能另写 `impl` 断言，不写进 `case`；文案行带【待确认】的拍板前不锁 | 别的校验也会抛同类异常，测试绿了却不是因为被测规则 |
| 7 | 期望值不得等于 mock 夹具原值 | 同义反复：把生产方法改成硬编码返回夹具值，测试照样绿 |
| 8 | 判据是公式的，夹具里每个因子都取**非平凡值**（≠0、≠1、互不相等，舍入位有尾数），至少两组数据；标准是「任一因子漏算或算错，断言都会红」 | 选 B=1 让「少乘一个系数」的实现也通过 |
| 9 | 断言必须**无条件可达**：不包在 `if` 里、不放在可能不执行的回调或流里；`try/catch` 捕到异常必须 `fail()` | 断言写了但执行不到，等于没写 |
| 10 | **不 spy 被测类、不 `doReturn` 被测方法**。mock 只打在协作方上 | 把被测逻辑本身换掉的测试测的是 mock |

自检一句话：对每个测试方法回答「**怎样改坏生产码它仍绿**」。答得出来就是漏洞，补到答不出来为止。
